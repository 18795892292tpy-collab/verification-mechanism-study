## 原协议状态

V3 为虚构学校制度的 `simulation_only` 开发实验。原冻结 P0 计划 80 题，实际尝试 80 次；严格状态为 {'technical_failure': 80}，完整 0 次。原 `analysis/decision_gate.json` 保持 **technical_block / challenge_allowed=false**；严格失败计入计划分母不能解释为模型实体决定全部错误。

CLI 输出包含配置诊断；原冻结规则将 error item 一律按失败处理。之后的 A1 是明确标注的**事后敏感性分析**，对精确诊断例外、事件顺序和原始回答进行核验，得到运输可接受 80/80、行动正确 80/80。其门槛诊断为 `development_gate_failed`，**不是原运行门槛，也不能授权原挑战**。事后例外不证明未知隐藏上下文无影响。
