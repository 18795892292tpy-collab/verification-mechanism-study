方法：同一个共享选择器供 scorer、branch_report、branch_pooled 和 runner 使用，按最早完成的完整成功分支选整组；核对首轮全文 SHA-256、完整首轮调用对象，以及复核实际重放的全文。重试不得逐程序混拼。解析失败或截断不按答案表现剔除或重试。详细规则与运行命令见 `../harness/INTEGRITY.md`。

花费：没有附可核验且适用于每次调用时段的价格表，三目录的货币总花费均为 NA；JSON 保留真实 usage 合计和缺失计数。不能从当前价格或历史报告中的概算反推精确实际花费。

验证：Python 3.12.13、SciPy 1.18.1 的任务专用环境中，19 项离线/mock 测试通过，包含跨进程锁争用及 5 项完整 CLI 报表测试。后者覆盖首轮全对、首轮全错、只有缺失证据题、复核结果全平局以及真实不一致对，确保零分母和无可检验差异时显示 NA，同时保留有数据支持的合法 p=1。四个修改后的入口及两个新模块通过语法编译，`git diff --check` 通过。

真实历史数据的完整离线集成已执行：分别生成两个推理目录的 branch_report，再用 branch_pooled 合并，得到 88 个完整组、616 条程序记录；这批数据的关键证据在场首轮错误为 0，因此六种复核的修复率及全部修复比较显示 NA，不能解释为效果为零或方法等价。报表在临时验证目录生成，未覆盖历史报表；输入中的 36 个受 Git 跟踪的原始回答/原始评分文件全部与固定提交 SHA-256 相同，验证前后也未改变。完整校验信息和报表哈希见 JSON 的 `full_integration_validation`。
