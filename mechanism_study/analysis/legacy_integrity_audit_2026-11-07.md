# 旧工具链修复后的只读复算

对应 Issue #2 任务 1。原目标是修复分支评分、续跑及审计的完整性缺陷；没有调用任何模型，也没有改写历史原始回答或历史评分表。

方法：同一个共享选择器供 scorer、branch_report、branch_pooled 和 runner 使用，按最早完成的完整成功分支选整组；核对首轮全文 SHA-256、完整首轮调用对象，以及复核实际重放的全文。重试不得逐程序混拼。解析失败或截断不按答案表现剔除或重试。详细规则与运行命令见 `../harness/INTEGRITY.md`。

|---|---:|---:|---:|---:|---:|---:|
| flash_branch_dev | 160 | 31 | 31 | 0 | 0 | 0 |
| flash_think_branch_dev | 160 | 52 | 49 | 3 | 0 | 0 |
| flash_think_branch_hard | 240 | 39 | 39 | 0 | 0 | 0 |

结果：三目录选中 217、343、273 条程序记录，全部最终答案可解析。推理条件合计仍为 88/400 个唯一完整组，剩余 312 组。以上数字与此前只读审计一致；52 是分支尝试数，不能当作唯一组数。输入文件逐个 SHA-256 与固定提交 `cf8a5b64bb221882348c0091f401a0e1f4847d24` 的 Git blob 原始内容一致。完整分支清单、token 计量及输入哈希见同名 JSON。

花费：没有附可核验且适用于每次调用时段的价格表，三目录的货币总花费均为 NA；JSON 保留真实 usage 合计和缺失计数。不能从当前价格或历史报告中的概算反推精确实际花费。

验证：Python 3.12.13 上 14 项离线/mock 测试通过，包含跨进程锁争用。四个修改后的入口及两个新模块通过语法编译，`git diff --check` 通过。旧 H04 两个 CSV 的 400/560 行均通过原始记录与现评分规则逐列兼容校验；第一轮 H04 的 branch_report 可离线生成。这不等于重新完成全部历史 H04 合并推断审计。

解释及限制：完整组选择缺陷已由针对性失败样例覆盖，不能据此宣称研究假说获支持。原有未经过独立教育专家审查的局限不变。Windows 锁路径尚未在 Windows 测试；本机缺少 scipy，branch_pooled 已做语法及共用读取器测试，但完整统计集成测试尚未执行，发布前应在安装仓库依赖的环境补跑。所有测试仅使用 Mock，无付费调用。
